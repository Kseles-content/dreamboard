# Простая статистика DreamBoard

Отдельный процесс Python/SQLite на 127.0.0.1:8788. Nginx публикует только POST /dreamboard-api/events. Никаких сторонних зависимостей, аккаунтов посетителей или постоянных идентификаторов. Отчёт по SSH, публичного API чтения нет.

Тело до 256 байт: только event, source, environment. Неизвестные поля и значения отклоняются; SQL параметризован. Origin проверяется, но его можно подделать: это не аутентификация. Счётчики ориентировочные, бот способен накручивать допустимые события. Preview отделён от production, но признак приходит с клиента и не доказывает происхождение события.

Nginx: 30 запросов/мин на сетевой адрес (burst 10), суммарно 10/с (burst 20), короткие таймауты, отсутствие access log на маршруте. IP используется nginx временно для ограничения частоты и не передаётся службе. Ошибки маршрута не пишутся в error log. Общие журналы инфраструктуры за пределами этого location не покрываются этим правилом.

Служба: DynamicUser, только каталог состояния доступен для записи, NoNewPrivileges, память 96 МБ, CPU 20%. Nginx буферизует запрос перед передачей процессу. Эти ограничения уменьшают риск, но не заменяют обновления ОС/nginx и защиту хостинга от DDoS.

Установка: скопировать каталог в /opt/dreamboard-statistics, запустить python3 deploy.py. Скрипт проверяет ожидаемый участок nginx, сохраняет копию и возвращает конфигурацию при ошибке. Повторную установку намеренно блокирует до проверки существующего состояния.

Закрытый CSV:

```sh
ssh root@45.139.77.52 'python3 /opt/dreamboard-statistics/server.py --report' > statistics.csv
```

Даты UTC, строки — суточные суммы. landing_view — загрузки лендинга; app_open_click — переходы по кнопкам; app_open — запуск кода; install_help_open — открытие инструкции; appinstalled — ограниченный сигнал браузера; standalone_open — запуск самостоятельного окна; png_ready — подготовка PNG; png_download_click — нажатие скачивания. Это не уникальные люди и не подтверждение записи файла. Офлайн, отключение статистики, DNT, блокировщики и ограничения частоты приводят к пропускам. Ретроспективного учёта нет.

Источник: ?utm_source=telegram, personal или pilot; остальные значения становятся unknown. Метка переносится с лендинга в приложение без постоянного хранения.

Очистка агрегатов старше 365 дней выполняется при записи и чтении отчёта. Для соблюдения срока при отсутствии трафика серверу нужна ежедневная задача вызова --report. Бэкап SQLite — команда --backup /защищённый/путь.sqlite3, использующая SQLite backup API. При восстановлении остановить службу, заменить только counts.sqlite3 проверенной копией, сохранить владельца/права и запустить службу. Резервная копия сервера не содержит пользовательских досок.

Откат: убрать ровно include статистики из nginx, выполнить nginx -t и reload, остановить и отключить dreamboard-statistics. Поиск фото и другие службы не затрагивать. Frontend можно вернуть предыдущим коммитом; его выключенный сборщик не препятствует работе доски.
