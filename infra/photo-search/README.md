# Сервер поиска фотографий

Подготовка, не опубликованный сервис. Node 22+, без npm-зависимостей. Используется существующий сервер; Supabase, подписка и запросы для поддержания активности не нужны.

Проверено 8 сентября: SSH root на 45.139.77.52 доступен; Node 22.23.2, nginx 1.24.0, HTTPS kseles.ru отвечает 200. Существующий HTTPS server block слушает 127.0.0.1:8444; другие маршруты и службы не изменены. Рабочая копия /srv/dreamboard содержит чужие незакоммиченные изменения и не использовалась для установки. Файлы подготовлены отдельно в /opt/dreamboard-photo-search; /etc/dreamboard-photo-search.env создан пустым, root:600. systemd unit проверен, но не установлен и не запущен; nginx snippets не включены. Пользователь подтвердил наличие ключа Pexels, место хранения уточняется.

Запуск: `node infra/photo-search/server.cjs`. Через окружение процесса задать `PEXELS_API_KEY`, `PHOTO_SEARCH_ORIGINS` (точные разрешённые origins через запятую, например `https://kseles-content.github.io`), опционально `PHOTO_SEARCH_PORT` (по умолчанию 8787). Ключ хранить только на сервере, не в GitHub, config.js или чате. Обработчик слушает исключительно 127.0.0.1; публиковать через существующий HTTPS reverse proxy, отдельным процессом системного менеджера, без плановых keepalive-запросов.

Контракт: `GET /api/photos?q=море&page=1`, заголовок Origin. Ответ: `photos[{id,title,url,thumbnail,author,sourceUrl,authorUrl}]`, `page`, `hasMore`, `provider`. Страница — 18 фото, максимум 20 страниц. Ошибки: 400 invalid_query, 403 origin_not_allowed, 429 rate_limited, 502 provider_unavailable, 503 not_configured.

Кэш в памяти на сутки, максимум 256 запросов, объединение одновременных одинаковых запросов. Локальный предел — 180 обращений к провайдеру в час на процесс; после upstream 429 пауза на час. Квота аккаунта общая для всех его использований, провайдер остаётся окончательным источником ограничений. Перезапуск очищает локальные счётчики и кэш, поэтому запускать один экземпляр; не использовать рестарты для обхода квоты. Перед публичным запуском настроить ограничение частоты на существующем reverse proxy: CORS не является защитой от прямых запросов сторонних клиентов.

Следующее после получения адреса: проверить установленный reverse proxy и менеджер процессов, приготовить конфигурацию под конкретный сервер, установить ключ через защищённое окружение, проверить реальный ответ и ошибки. Затем подключить клиентскую вкладку «В сети»: отмена устаревшего запроса, «Ещё», повтор, превью и указание автора/Pexels. Добавить точный HTTPS-домен обработчика и images.pexels.com в CSP, атрибуцию в карточке/просмотре с сохранением метаданных. Сейчас клиент не изменён и сетевой поиск в preview не включён.

Проверки `node --test photo-search.test.js` используют подмену провайдера; они проверяют логику сервера, а не действительность ключа, доступность внешнего API или условия конкретного хостинга.

Официальный контракт и требования атрибуции: https://www.pexels.com/api/documentation/ (проверено 8 сентября 2026). Pexels запрещает копирование основной функциональности фотобиблиотеки, включая wallpaper-приложения. DreamBoard использует фотографии как часть пользовательской композиции; перед включением будущего экспорта уточнить соответствие выбранного сценария условиям, не обещать бессрочные правила внешнего сервиса.
