## Сделано

- Вместо светящегося пятна — двухцветный символ инь-ян. На вдохе он плавно растёт
  с 31 до 48 px, остаётся большим на задержке, сжимается на выдохе и остаётся
  маленьким в фазе покоя. Фазы прежние: по 4 секунды.
- В мобильном lite-профиле разрешена только эта функциональная transform-анимация;
  тяжёлые тени, фоновые эффекты и Ken Burns не возвращались. Системная настройка
  уменьшения движения отключает масштабирование, текст фаз продолжает работать.
- Круг и фаза занимают отдельную строку над доской. Телефон больше не требует
  поворота для просмотра. Изображение помещается целиком; в коротком landscape
  фото и текст расположены рядом. На сверхнизком экране доступна прокрутка.
- Увеличены кнопки управления до 44 px; добавлены названия для экранного диктора.
- Звук: четыре чистых синусоидальных тона C–E–G с нижней октавой C, без расстройки,
  случайных переливов и звуков при смене доски. Громкость плавно следует дыханию.
  Звук по умолчанию выключен; отдельная кнопка доступна в манифестации.
- Звук останавливается при уходе со вкладки и выходе из режима. Исправлена гонка,
  при которой завершение старого синтезатора могло остановить новый.
- Новый CSS включён в PRECACHE, версия scoped-кэша повышена до v16.

## Что подготовлено для основного репозитория

Ветка `feat/auth-ux-breath-candidate` содержит мобильные изменения и пять
проверенных preview-исправлений: контраст полей, показ пароля, CAPTCHA для входа
и сброса, распознавание recovery-ссылки, корректные состояния форм.

Production-загрузчик Supabase сохранён: SDK загружается динамически и только
при включённом и корректно настроенном входе. Нельзя копировать preview целиком:
в нём другой способ подключения SDK и включённая sandbox-конфигурация.

`config.js` основного приложения остаётся с `authEnabled:false`. Включение входа
требует проверки production Site URL / redirect allowlist в Supabase, публичных
параметров Turnstile и реального теста письма восстановления на основном адресе.
Это внешний незавершённый шаг, а не автоматическая часть переноса интерфейса.
Облачная синхронизация не включалась; контракты данных и локальные хранилища не менялись.

## Проверки

- 285/285 Node-тестов, включая четыре новых проверки звукового жизненного цикла
  и проверку передачи CAPTCHA при входе и восстановлении пароля.
- Браузерная проверка Chromium: 390×844, 800×360, 320×568, 640×200,
  1024×768, 1440×900 и 390×844 с reduced motion.
- Проверяются отсутствие пересечений круга и доски, видимость изображений,
  реальный lite-профиль, фазы дыхания, переключение досок, пауза слайдов,
  включение/выключение звука и повторный старт, отсутствие JS-ошибок.
- В браузерной матрице Fullscreen API намеренно отклоняется для проверки
  обычного мобильного режима; отдельно проверено открытие настоящего fullscreen.
- Синтаксис изменённого JS и `git diff --check`.

Запуск: `node --test *.test.js` из корня репозитория. Для браузерной матрицы:
запустить `python -m http.server 8765 --bind 127.0.0.1` из корня, затем
`python scripts/qa-manifest.py`. Требуется установленный Python Playwright/Chromium.
Можно задать `DREAMBOARD_QA_URL` для другой локальной копии.

Эмуляция не заменяет прослушивание и проверку производительности на физическом
TCL 30 / iPhone. Реальная авторизация повторно не выполнялась: учётные записи,
почта и настройки Supabase не изменялись.

## Следующие улучшения дизайна и удобства

1. Упорядочить адаптивный CSS. В `style.css` накопилось несколько пересекающихся
   правил для 900/760 px и высот 620/520/500 px. Именно их конфликт ломал
   расположение подписи дыхания. Новая вёрстка изолирована в `manifest-breath.css`;
   дальнейшую уборку делать отдельно с сохранением скриншотов и проверок.
2. Уменьшить шум в манифестации: уведомления о звуке уже убраны из просмотра,
   состояние видно по кнопке. Следующий кандидат — короткое сообщение о паузе,
   которое на desktop временно перекрывает нижнюю часть изображения.
3. Упростить первый запуск: явно объяснить, где сохраняются доски и как сделать
   резервную копию. Регистрация сейчас не означает синхронизацию между устройствами.
4. Перед реальными пользователями вынести preview на отдельный hostname.
   Сейчас preview и production на одном origin GitHub Pages; browser storage
   может быть общим несмотря на разные пути. Scoped-кэши изолированы, но это
   не изолирует localStorage/IndexedDB.

Следующий продуктовый этап — включение уже подготовленной авторизации после
проверки внешней конфигурации. Облачную синхронизацию начинать отдельным этапом.
