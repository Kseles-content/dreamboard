## Сервер

Статический сайт размещён на GitHub Pages. На сервере `45.139.77.52` работают отдельные сервисы:

| Сервис | Каталог | Локальный порт | Инструкция |
| --- | --- | --- | --- |
| `dreamboard-statistics` | `/opt/dreamboard-statistics` | `127.0.0.1:8788` | [Статистика](../../infra/statistics/README.md) |
| `dreamboard-photo-search` | `/opt/dreamboard-photo-search` | `127.0.0.1:8787` | [Фото](../../infra/photo-search/README.md) |

Nginx публикует `/dreamboard-api/events` и `/dreamboard-api/photos` на `kseles.ru`. Доступ к обслуживанию — по SSH администратора. Проверка службы: `systemctl status dreamboard-statistics`; журнал: `journalctl -u dreamboard-statistics`. Аналогично для поиска фото. Перед применением nginx проверяйте `nginx -t`.

Секрет поиска находится в `/etc/dreamboard-photo-search.env`; не переносите его в документацию или клиентский код. Изменение одной службы не должно затрагивать другую.

## Отчёт и резервная копия статистики

```sh
ssh root@45.139.77.52 'python3 /opt/dreamboard-statistics/server.py --report' > statistics.csv
```

База: `/var/lib/dreamboard-statistics/counts.sqlite3`. На дату проверки установлена ежедневная задача `/etc/cron.d/dreamboard-statistics` в 03:17 по времени сервера: очистка через `--report` и копия через SQLite backup API в `/var/lib/dreamboard-statistics/latest-backup.sqlite3`. Права базы и копии — 600. Копия на том же сервере не защищает от потери всего сервера; внешнее хранение — отдельная задача.

Для восстановления остановите службу, сохраните текущую базу, проверьте целостность копии, замените базу с сохранением владельца и прав, запустите службу и проверьте отчёт. Детали — в инструкции сервиса. Эта копия не содержит досок: они восстанавливаются из пользовательского JSON.

## Диагностика

- Нет событий: проверьте отключение статистики/DNT, маршрут и службу. Пропуски допустимы; повторной очереди нет.
- Нет внешних фото: проверьте службу поиска, поставщика и сеть; встроенные изображения проверяйте отдельно.
- Старая версия: сравните `version.txt`, публикацию и service worker. Перед очисткой данных сайта сохраните JSON.
- Ошибка после выпуска: используйте [процедуру отката](DEVELOPMENT.md), затем проверьте публичную версию.
