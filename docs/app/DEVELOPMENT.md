# Разработка, проверка и выпуск

[К документации](../README.md) · Обновлено 2026-09-10.

## Запуск и тесты

Из корня репозитория: `python -m http.server 8000 --bind 127.0.0.1`. Откройте `http://127.0.0.1:8000/`, `/welcome/` или `/welcome/banner/`. Сборки текущего фронтенда нет.

Для JavaScript-тестов используется Node.js 22. В PowerShell явно соберите список файлов:

```powershell
$testFiles = Get-ChildItem -File *.test.js | Select-Object -ExpandProperty FullName
node --test $testFiles
python -m unittest discover -s infra/statistics -p 'test_*.py'
```

В Bash: `node --test *.test.js`. Для синтаксиса используйте `node --check app.js` и аналогично для изменённых файлов. npm-команды прежнего сервера не заменяют проверки текущей PWA.

Проверяйте изменённый сценарий в браузере на настольной и мобильной ширине. Для импорта используйте тестовые данные. Для дыхания — обе паузы, обратное вращение, остановку и уменьшение движения. Для звука — включение, выключение, повторный запуск и офлайн. Для баннера — размер PNG, обрезку и ссылку.

## Выпуск

Основной репозиторий — `Kseles-content/dreamboard`, ветка `main`; предварительный — `Kseles-content/dreamboard-v14-preview`. В рабочей папке им соответствуют `production-review` и `preview-review`.

1. Создайте ветку, измените код и документацию, просмотрите diff.
2. Выполните проверки затронутых функций; не добавляйте секреты и пользовательские данные.
3. Для изменения поведения проверьте предварительную публикацию и создайте PR в основной репозиторий.
4. Дождитесь обязательных CI-проверок. Здесь также запускаются проверки прежнего сервера и мобильного прототипа; это не означает публикацию APK.
5. Зафиксируйте точку отката, слейте проверенный PR, дождитесь GitHub Pages.
6. На публичном адресе проверьте версию и изменённый сценарий, а при изменении PWA — обновление и офлайн.

При изменении ресурсов согласуйте `version.txt`, версию кэша в `service-worker.js` и ссылки с параметрами версии. Проверьте `PRECACHE_URLS` и обновление уже установленного приложения. Только Markdown не требует обновления кэша.

Workflow `.github/workflows/static-app.yml` проверяет PWA и статистику, `.github/workflows/ci.yml` — остальные части. Запуск зависит от путей изменённых файлов.

## Откат и документация

Предпочтителен revert-коммит через PR с сохранением истории. При откате PWA назначайте новую версию сборки и кэша: часть пользователей уже могла получить новый service worker. Серверные сервисы откатываются отдельно по их инструкциям. Затем проверьте публичную версию и сохранность тестовой доски.

Обновляйте руководство пользователя при изменении поведения, архитектуру — при изменении данных, эксплуатацию — при изменении обслуживания. CHANGELOG должен описывать фактические изменения и результаты проверок.
